## What to build

Add a test for rule **MA0233** — *An abstract EventSource must not declare event methods* — from
the `Meziantou.Analyzer` analyzer.

An abstract `EventSource` is never instantiated directly, and ETW builds its manifest from the
concrete type. Event methods declared on the abstract base are therefore not reliably part of any
derived source's manifest.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzersEventSourceShould.cs` (created by issue 001):

```csharp
[Fact]
[RuleDoc("MA0233", "An abstract EventSource must not declare event methods",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0233.md")]
public async Task ProhibitEventMethodsOnAbstractEventSource()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        using System.Diagnostics.Tracing;
        namespace test;
        public abstract class MyEventSourceBase : EventSource
        {
            [Event(1)]
            public void Started(string message) => WriteEvent(1, message);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0233").ShouldBeTrue();
}
```

### Watch out for

- **This class cannot be `sealed`** — `abstract` is the whole point of the rule. If `MA0226`
  (EventSource should be sealed) also fires on the abstract type, that is acceptable: the
  assertion is specifically `HasError("MA0233")` and a second diagnostic in the same SARIF file
  does not affect it. Do not try to suppress `MA0226` inline — AGENTS.md forbids inline
  suppressions in this repo.
- Keep the `WriteEvent` id and payload correct so `MA0234` / `MA0235` do not fire as well.
- If the rule does not fire on an abstract class with no derived type, add a concrete
  `public sealed class MyEventSource : MyEventSourceBase { }` below it — the analyzer may only
  report once the hierarchy is realised.

## Confounder playbook (exhaust before marking untestable)

`System.Diagnostics.Tracing.EventSource` is in the BCL on `net10.0`, so no `PackageReference` is
needed and this rule is expected to be straightforwardly testable. If it does not fire, work
through the standard playbook in AGENTS.md in order:

1. **Add a package reference** — not applicable; `EventSource` is in the BCL.
2. **Use stub types** — not applicable; the real `EventSource` is available.
3. **Pin `LangVersion=12`** — only if overload routing on `WriteEvent` looks suspect.
4. **Set `ignore_internalsvisibleto=true`** — try if the rule appears friend-assembly sensitive.
5. **Check `EnforceOnBuild`** in the analyzer source (`EnforceOnBuild.Never` is structurally silent
   at build).
6. **Check the reporting analyzer's assembly path** (`src/Features/` = IDE-only).
7. **Check the mscorlib gate** — not applicable to a Meziantou rule.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
