## What to build

Add a test for rule **MA0228** — *The event id of an EventSource must be greater than zero* — from
the `Meziantou.Analyzer` analyzer.

ETW reserves event id `0`, and negative ids are invalid outright. An `[Event]` attribute declaring
an id of `0` or less produces an `EventSource` whose manifest fails to build at runtime — silently,
because `EventSource` swallows construction errors by design.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzersEventSourceShould.cs` (created by issue 001):

```csharp
[Fact]
[RuleDoc("MA0228", "The event id of an EventSource must be greater than zero",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0228.md")]
public async Task RequireEventIdGreaterThanZero()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        using System.Diagnostics.Tracing;
        namespace test;
        public sealed class MyEventSource : EventSource
        {
            [Event(0)]
            public void Started(string message) => WriteEvent(0, message);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0228").ShouldBeTrue();
}
```

### Watch out for

- **Keep the class `sealed`** — otherwise `MA0226` fires as well and the result is ambiguous.
- **Keep `WriteEvent`'s id equal to the `[Event]` id** (both `0` above). Writing a different id
  would additionally trip `MA0234`, which is issue 009's rule.
- If `0` does not fire, try a negative id (`[Event(-1)]` with `WriteEvent(-1, message)`) — both are
  covered by "must be greater than zero".
