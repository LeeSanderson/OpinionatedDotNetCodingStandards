## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzers3Should.cs`:

```csharp
[Fact]
[RuleDoc("MA0221", "TryGetValue method should use [MaybeNullWhen(false)] on the value parameter",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0221.md")]
public async Task UseMaybeNullWhenFalseOnTryGetValueOutParameter()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        namespace test;
        public static class Lookup
        {
            public static bool TryGetValue(string key, out string value)
            {
                value = key;
                return true;
            }
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();
    buildOutput.HasError("MA0221").ShouldBeTrue();
}
```

The rule targets a method **named `TryGetValue`** that returns `bool` and has an `out` parameter
whose type is a reference type (or otherwise nullable-annotatable) that is **not** decorated with
`[MaybeNullWhen(false)]`. Read
`https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0221.md` and, if needed,
the analyzer's report predicate in the Meziantou.Analyzer source before assuming the shape above
is exactly right.

Things to try if the first probe stays silent:

- Nullable context matters for this family of rules. The harness project may not have
  `<Nullable>enable</Nullable>` set — if the analyzer only reports inside an enabled nullable
  context, add it via `properties: [("Nullable", "enable")]` on `CreateProjectBuilderAsync`.
- Try both `out string value` and `out string? value`; the analyzer may only flag the
  non-annotated form, or only the annotated-but-unattributed form.
- Try an instance method on a non-static class as well as the static form above, and try a
  `TryGetValue<TValue>(string key, out TValue value)` generic overload.

Note the neighbouring rules MA0222–MA0225 are being added in the same PRD but are unrelated to
this one — don't conflate them.

## Confounder playbook (exhaust before marking untestable)

Work through these in order:

1. **Add a package reference** if the rule guards on types in an external package:
   - Logging rules (`CA1727`, `CA1848`, `CA2253`, `CA2254`, `CA2017`, `CA1873`, `CA2023`):
     add `("Microsoft.Extensions.Logging.Abstractions", "10.0.0")` to `packageReferences`.
   - ASP.NET Core MVC rules (`CA5391`, `CA5395`):
     add `("Microsoft.AspNetCore.Mvc", "2.3.10")` and set
     `properties: [("NuGetAudit", "false"), ("NoWarn", "NU1903;NU1902;CA1515;CA1822")]`.

   For MA0221 specifically, `[MaybeNullWhen]` lives in
   `System.Diagnostics.CodeAnalysis` in the `net10.0` BCL — no package needed.

2. **Use stub types** if the rule merely requires a type to exist in the compilation (no real
   package needed — just declare a matching type with the right name/namespace in `Program.cs`).

3. **Pin `LangVersion=12`** if C# 13 might route single-argument calls to a new `ReadOnlySpan`
   overload that the analyzer can't match (known to affect `CA1842`, `CA1843`).

4. **Set `ignore_internalsvisibleto=true`** on `CreateProjectBuilderAsync` if the rule is
   friend-assembly-sensitive (e.g., `CA1852`).

5. **Check `EnforceOnBuild` in Roslyn source** — rules tagged `EnforceOnBuild.Never` are
   structurally silent at `dotnet build` regardless of editorconfig severity. If confirmed,
   mark untestable and cite the source file + the `EnforceOnBuild.cs` / `EnforceOnBuildValues.cs`
   reference. (Applies to `IDE` rules only — not relevant for `MA` rules.)

6. **Check the reporting analyzer's assembly path** — if the reporting class lives in a
   `src/Features/` path (not `src/Analyzers/`), it is IDE/LSP-only and cannot run at build time.
   Mark untestable and cite the path.

7. **Check mscorlib gate** — rules that assert `System.String` is in `mscorlib` cannot fire on
   `net10.0` (it lives in `System.Private.CoreLib`). Mark untestable with that explanation.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
