## What to build

Add a test for rule **MA0237** — *An EventSource event method writing a related activity id must
declare it as its first parameter* — from the `Meziantou.Analyzer` analyzer.

`EventSource.WriteEventWithRelatedActivityId(int eventId, Guid relatedActivityId, params object[]
args)` emits a transfer event. ETW requires the related activity id to be the event method's
**first** parameter — that is how the runtime knows to treat it as the transfer target rather than
as an ordinary `Guid` payload field.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzersEventSourceShould.cs` (created by issue 001):

```csharp
[Fact]
[RuleDoc("MA0237", "An EventSource event method writing a related activity id must declare it as its first parameter",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0237.md")]
public async Task RequireRelatedActivityIdAsFirstParameter()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        using System;
        using System.Diagnostics.Tracing;
        namespace test;
        public sealed class MyEventSource : EventSource
        {
            [Event(1)]
            public void Started(string message, Guid relatedActivityId) =>
                WriteEventWithRelatedActivityId(1, relatedActivityId, message);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0237").ShouldBeTrue();
}
```

The **correct** shape the rule is steering towards — useful as the negative control if you need one
— puts the id first:

```csharp
[Event(1)]
public void Started(Guid relatedActivityId, string message) =>
    WriteEventWithRelatedActivityId(1, relatedActivityId, message);
```

### Watch out for

- **Keep the class `sealed`** — otherwise `MA0226` fires as well.
- `WriteEventWithRelatedActivityId` is `protected`, so it can only be called from inside the derived
  class — which is exactly where this code sits.
- **`MA0235` / `MA0236` may fire alongside this one.** The related activity id is conventionally
  excluded from the payload, so an analyzer comparing `WriteEventWithRelatedActivityId`'s args
  against the full parameter list could see a mismatch. That is acceptable — the assertion targets
  `MA0237` specifically. Only if `MA0237` itself is missing should you adjust the shape.
- Keep the written id matching the `[Event]` id (both `1`) so `MA0234` does not fire.
- `using System;` is needed for `Guid`.

## Confounder playbook (exhaust before marking untestable)

`System.Diagnostics.Tracing.EventSource` is in the BCL on `net10.0`, so no `PackageReference` is
needed and this rule is expected to be straightforwardly testable. If it does not fire, work
through the standard playbook in AGENTS.md in order:

1. **Add a package reference** — not applicable; `EventSource` is in the BCL.
2. **Use stub types** — not applicable; the real `EventSource` is available.
3. **Pin `LangVersion=12`** — worth trying: the `params object[]` tail can route differently under
   C# 13 than the analyzer matches.
4. **Set `ignore_internalsvisibleto=true`** — try if the rule appears friend-assembly sensitive.
5. **Check `EnforceOnBuild`** in the analyzer source (`EnforceOnBuild.Never` is structurally silent
   at build).
6. **Check the reporting analyzer's assembly path** (`src/Features/` = IDE-only).
7. **Check the mscorlib gate** — not applicable to a Meziantou rule.

If the rule still does not fire, try a shape where the `Guid` parameter is present but the method
has no other parameters at all (`public void Started(Guid relatedActivityId)` is the *valid* form,
so instead try `public void Started(string message)` writing `Guid.Empty` as the related id), which
tests the "not declared as a parameter" variant of the same rule.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
