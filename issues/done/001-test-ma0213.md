## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzers3Should.cs`:

```csharp
[Fact]
[RuleDoc("MA0213", "Simplify negated boolean expression",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0213.md")]
public async Task SimplifyNegatedBooleanExpression()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        namespace test;
        public static class C
        {
            public static bool M(bool first, bool second) => !(!first && second);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();
    buildOutput.HasError("MA0213").ShouldBeTrue();
}
```

### Why that exact shape

A bare negated comparison such as `!(a == b)` does **not** fire MA0213. The analyzer
(`SimplifyNegatedBooleanExpressionAnalyzer`) requires all of:

1. a built-in logical `!` on a `bool`,
2. whose operand is a `&&` or `||` binary expression (a plain comparison is rejected),
3. where both operands can be negated, and
4. where at least one operand is itself `!x`.

`!(!first && second)` satisfies all four. Fallbacks: `!(!first || !second)` or `!(!first || second)`.

## Confounder playbook (exhaust before marking untestable)

Work through these in order:

1. **Add a package reference** if the rule guards on types in an external package.
2. **Use stub types** if the rule merely requires a type to exist in the compilation.
3. **Pin `LangVersion=12`** if C# 13 might route a call to a new `ReadOnlySpan` overload the
   analyzer can't match.
4. **Set `ignore_internalsvisibleto=true`** on `CreateProjectBuilderAsync` if the rule is
   friend-assembly-sensitive.
5. **Check `EnforceOnBuild` in the analyzer source** — rules tagged `EnforceOnBuild.Never` are
   structurally silent at `dotnet build`.
6. **Check the reporting analyzer's assembly path** — a `src/Features/` path means IDE/LSP-only.
7. **Check the mscorlib gate** — rules asserting `System.String` lives in `mscorlib` cannot fire
   on `net10.0`.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
