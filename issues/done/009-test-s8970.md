## How to implement the test

```csharp
[Fact]
[RuleDoc("S8970", "Null-forgiving operators should not be used when nullable warnings are disabled",
    HelpLink = "https://rules.sonarsource.com/csharp/S8970/")]
public async Task ProhibitNullForgivingOperatorsWhenNullableWarningsDisabled()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        #nullable disable
        namespace test;
        // TODO: add code that triggers S8970 (a `!` null-forgiving operator used while
        // nullable warnings are disabled for the file/project)
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();
    buildOutput.HasError("S8970").ShouldBeTrue();
}
```

## Confounder playbook (exhaust before marking untestable)

Work through these in order:

1. **Add a package reference** if the rule guards on types in an external package.
2. **Use stub types** if the rule merely requires a type to exist in the compilation.
3. **Pin `LangVersion=12`** if C# 13 might route single-argument calls to a new `ReadOnlySpan`
   overload the analyzer can't match.
4. **Set `ignore_internalsvisibleto=true`** if the rule is friend-assembly-sensitive.
5. **Check `EnforceOnBuild` in Roslyn source** — rules tagged `EnforceOnBuild.Never` are
   structurally silent at `dotnet build` regardless of editorconfig severity.
6. **Check the reporting analyzer's assembly path** — `src/Features/` = IDE/LSP-only, cannot
   run at build time.
7. **Check mscorlib gate** — rules asserting `System.String` is in `mscorlib` cannot fire on
   `net10.0`.

Note: the project-wide `Nullable` MSBuild property (or a per-file `#nullable disable`) is
probably what this rule actually gates on — check the analyzer's real trigger condition before
assuming the simple repro above is sufficient.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
