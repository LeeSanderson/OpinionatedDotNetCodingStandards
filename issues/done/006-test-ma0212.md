## Confounder playbook (exhaust before marking untestable)

Work through these in order:

1. **Add a package reference** if the rule guards on types in an external package.
2. **Use stub types** if the rule merely requires a type to exist in the compilation.
3. **Pin `LangVersion=12`** if C# 13 might route single-argument calls to a new `ReadOnlySpan`
   overload the analyzer can't match.
4. **Set `ignore_internalsvisibleto=true`** if the rule is friend-assembly-sensitive.
5. **Check `EnforceOnBuild` in Roslyn source** — rules tagged `EnforceOnBuild.Never` are
   structurally silent at `dotnet build` regardless of editorconfig severity.
6. **Check the reporting analyzer's assembly path** — `src/Features/` = IDE/LSP-only, cannot
   run at build time.
7. **Check mscorlib gate** — rules asserting `System.String` is in `mscorlib` cannot fire on
   `net10.0`.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
