## What to build

Add a test for rule **MA0219** — *Set the language attribute in XML comment* — from the
`Meziantou.Analyzer` analyzer.

The rule fires when a `<c>` or `<code>` element in an XML doc comment does not indicate the
language of the code it contains.

## Severity — read this first

`MA0219` is deliberately configured as **`suggestion`**, not `warning`, in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`.
The rationale is recorded in that file's header and in the PRD: at `warning` it would break the
build of essentially any consumer that documents its API, and the `language` attribute is only a
non-standard convention (upstream ships the rule at `hidden` severity).

**Therefore assert with `HasNote("MA0219")`, not `HasError`** — the same pattern as the existing
`MA0215` and `MA0217` tests in this file. Do not "fix" the severity to make an `HasError`
assertion pass.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzers3Should.cs`:

```csharp
[Fact]
[RuleDoc("MA0219", "Set the language attribute in XML comment",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0219.md")]
public async Task RecommendLanguageAttributeInXmlComment()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        namespace test;
        public class C
        {
            /// <summary>
            /// Sample <c>{ "value": 1 }</c>.
            /// </summary>
            public int Value { get; set; }
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();
    buildOutput.HasNote("MA0219").ShouldBeTrue();
}
```

### Verified behaviour

This rule was confirmed to fire at build time during the package bump (it produced
`error MA0219` while still configured at `warning`), so it is definitely testable — do **not**
move it to `UntestableRules.cs`. After the deliberate downgrade to `suggestion` it should now
appear as a **note**.

### Watch out for

- **The content of the `<c>` element must not be a single C# keyword.** Upstream explicitly
  suppresses `MA0219` in that case because `MA0154` already suggests `<see langword="..." />`
  instead. So `<c>null</c>` or `<c>true</c>` will **not** fire. Use a non-keyword payload such as
  the JSON snippet above.
- **Use the multi-line `/// <summary>` form shown above.** A single-line
  `/// <summary>...</summary>` trips `MA0211` ("Use multi-line syntax for XML summary comments"),
  which would fail the build and mask the note.
- Do not add a `language` attribute — that is what the rule asks for, and an *empty* one triggers
  `MA0218` instead (issue 001).
