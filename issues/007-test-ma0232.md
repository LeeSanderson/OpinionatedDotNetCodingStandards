## What to build

Add a test for rule **MA0232** — *An EventSource event method must not be an explicit interface
implementation* — from the `Meziantou.Analyzer` analyzer.

An explicitly-implemented interface method is private and carries a mangled metadata name, so
`EventSource`'s reflective discovery never finds it and the event silently never fires.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzersEventSourceShould.cs` (created by issue 001):

```csharp
[Fact]
[RuleDoc("MA0232", "An EventSource event method must not be an explicit interface implementation",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0232.md")]
public async Task ProhibitExplicitInterfaceEventSourceEventMethod()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        using System.Diagnostics.Tracing;
        namespace test;
        public interface IMyEvents
        {
            void Started(string message);
        }
        public sealed class MyEventSource : EventSource, IMyEvents
        {
            [Event(1)]
            void IMyEvents.Started(string message) => WriteEvent(1, message);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0232").ShouldBeTrue();
}
```

### Watch out for

- **Keep the class `sealed`** — otherwise `MA0226` fires as well.
- The `[Event]` attribute must be on the *explicit implementation* in the class, not on the
  interface declaration — that is the shape the rule reports.
- Keep the `WriteEvent` id and payload correct so `MA0234` / `MA0235` do not fire alongside it.
- An explicit implementation cannot carry an access modifier; `void IMyEvents.Started(...)` is
  correct as written.
