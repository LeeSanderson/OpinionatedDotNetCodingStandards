## How the rule works

`MA0241` is the companion diagnostic to [`MA0240`](001-test-ma0240.md) — same analyzer,
`DoNotUseBannedSyntaxAnalyzer`. It reports the lines of a `BannedSyntaxes.txt` /
`BannedSyntaxes.*.txt` file that `MA0240` **cannot apply**, so that a typo does not silently
disable a ban. The diagnostic is reported on the offending line of the file, not on any C# code,
and the remaining valid lines of the file are still applied.

A line is invalid when:

- It is a single name (optionally preceded by `//`) that is not a member of `SyntaxKind`. Names are
  case-sensitive, so `gotostatement` is invalid.
- It is not a valid XPath 1.0 query, or uses a function that does not exist.
- The query does not return a node-set (e.g. `count(//ClassDeclaration)`).
- It uses a namespace prefix other than `semantic` (the only defined prefix).
- It uses a name that is not one of the `semantic` attributes, e.g.
  `//ClassDeclaration[@semantic:Typo='a']`.

The message is `The query '<query>' is not valid: '<query>' is not a member of SyntaxKind` for the
misspelled-kind case.

## How to implement the test

Add a `[Fact]` to
`tests/Opinionated.DotNet.CodingStandards.Tests/MeziantouAnalyzers/MeziantouAnalyzersCoreShould.cs`.
This is the direct analogue of `BannedApiAnalyzersShould.ReportDuplicateBannedSymbolEntry`, which
tests `RS0031` (the malformed-entry diagnostic for `BannedSymbols.txt`) the same way.

```csharp
[Fact]
[RuleDoc("MA0241", "The banned syntax entry is not valid",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0241.md")]
public async Task InvalidBannedSyntaxEntry()
{
    using var project = await CreateProjectBuilderAsync(additionalFiles: ["BannedSyntaxes.txt"]);
    // A single-name query must be an exact, case-sensitive SyntaxKind member. "GotoStatment" is a
    // typo for "GotoStatement", so MA0240 cannot apply the line and MA0241 reports it against the
    // BannedSyntaxes.txt line itself. No C# code needs to trigger anything here — the defect is
    // in the additional file, so a minimal Program.cs is enough.
    await project.AddFileAsync("BannedSyntaxes.txt", "GotoStatment; Use structured control flow instead");
    await project.AddFileAsync("Program.cs", """
        namespace test;
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0241").ShouldBeTrue();
}
```

Keep this test's invalid entry **separate** from `MA0240`'s valid entry — do not try to cover both
rules from one `BannedSyntaxes.txt`. Each rule needs its own `[RuleDoc]` on its own `[Fact]`, and a
single-purpose file makes each failure unambiguous.

## Confounder playbook (exhaust before marking untestable)

Work through these in order:

1. **Supply the additional file** — as with `MA0240`, the file is the trigger. Confirm the
   `AdditionalFiles` item reached the compiler and the file exists on disk before the build.
   Note the inverse trap of `MA0240`: here the entry must be **wrong**. If the misspelling
   accidentally matches a real `SyntaxKind` member, nothing is reported. Verify `GotoStatment`
   (or whatever typo is used) is genuinely not in
   https://github.com/dotnet/roslyn/blob/main/src/Compilers/CSharp/Portable/Syntax/SyntaxKind.cs.
2. **Diagnostic location** — `MA0241` is reported on a line of a **text file**, not on C# source.
   If it does not appear in SARIF, check whether the harness's ErrorLog captures diagnostics whose
   location is an additional file. `RS0031` in `BannedApiAnalyzersShould` proves this shape does
   land in SARIF, so treat an absence as a real gate rather than assuming a harness limitation.
3. **Add a package reference** / **stub types** / **`LangVersion=12`** /
   **`ignore_internalsvisibleto=true`** — none of these apply; the rule inspects a text file, not
   the compilation's types or overload resolution.
4. **Check `EnforceOnBuild` in Roslyn source** — not applicable; this is a Meziantou rule, and the
   regenerated editorconfig reports `Enabled: True, Severity: warning`.
5. **Check the reporting analyzer's assembly path** — `DoNotUseBannedSyntaxAnalyzer` is in
   `src/Meziantou.Analyzer/Rules/`, which ships in the analyzer assembly and runs at build.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
