## What to build

Add a test for rule **MA0229** — *The event id of an EventSource is already used by another event*
— from the `Meziantou.Analyzer` analyzer.

Event ids must be unique within an `EventSource`. Two event methods sharing an id produce a
manifest that cannot distinguish them, so consumers decode one event's payload using the other's
schema.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzersEventSourceShould.cs` (created by issue 001):

```csharp
[Fact]
[RuleDoc("MA0229", "The event id of an EventSource is already used by another event",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0229.md")]
public async Task ProhibitDuplicateEventId()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        using System.Diagnostics.Tracing;
        namespace test;
        public sealed class MyEventSource : EventSource
        {
            [Event(1)]
            public void Started(string message) => WriteEvent(1, message);

            [Event(1)]
            public void Stopped(string message) => WriteEvent(1, message);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0229").ShouldBeTrue();
}
```

### Watch out for

- **Keep the class `sealed`** — otherwise `MA0226` fires as well.
- **Give the two methods different names** (`Started` / `Stopped` above). Identical effective event
  names would additionally trip `MA0230`, which is issue 005's rule.
- **Keep each `WriteEvent` id matching its own `[Event]` id** so `MA0234` does not fire too.
