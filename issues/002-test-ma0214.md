## What to build

Add a test (or untestable declaration) for rule **MA0214** — *Use 'await' instead of returning the
task* — from the `Meziantou.Analyzer` analyzer.

## Shipped severity — read this before writing the assertion

MA0214 ships at **`suggestion`**, not `warning`. Assert with
`buildOutput.HasNote("MA0214").ShouldBeTrue()` — `HasError` will **not** match.

MA0214 is deliberately kept at `suggestion` because it is the exact inverse of **MA0215** and both
fire on the same expression; see the severity rationale in `issues/prd.md` and the header note in
`Analyzer.Meziantou.Analyzer.editorconfig`.

## How to implement the test

A known-firing shape: a non-async method whose body returns another async method's task directly.
This was observed firing on exactly this pattern:

```csharp
public static Task<int> DoAsync(string a) => DoAsync(a, CancellationToken.None);
```

Add a `[Fact]` to `MeziantouAnalyzers3Should.cs`:

```csharp
[Fact]
[RuleDoc("MA0214", "Use 'await' instead of returning the task",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0214.md")]
public async Task UseAwaitInsteadOfReturningTask()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        namespace test;
        using System.Threading;
        using System.Threading.Tasks;

        public static class Worker
        {
            // TODO: confirm the exact shape that trips MA0214 rather than MA0215.
            public static Task<int> RunAsync(string path)
                => RunAsync(path, CancellationToken.None);

            public static async Task<int> RunAsync(string path, CancellationToken token)
            {
                await Task.Delay(1, token);
                return path.Length;
            }
        }

        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();
    buildOutput.HasNote("MA0214").ShouldBeTrue();
}
```

**Careful:** MA0214 and MA0215 are inverses. If the code you write trips MA0215 instead, you have
the two shapes swapped — flip the form (return the task vs. `await` it) rather than assuming the
rule can't fire.

## Confounder playbook (exhaust before marking untestable)

1. **Add a package reference** if the rule guards on types in an external package.
2. **Use stub types** if the rule merely requires a type to exist in the compilation.
3. **Pin `LangVersion=12`** if C# 13 overload routing might redirect the call.
4. **Set `ignore_internalsvisibleto=true`** if the rule is friend-assembly-sensitive.
5. **Check `EnforceOnBuild`** — `EnforceOnBuild.Never` rules are silent at `dotnet build`.
6. **Check the reporting analyzer's assembly path** — `src/Features/` means IDE/LSP-only.
7. **Check the mscorlib gate** — not applicable to `net10.0` targets.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
