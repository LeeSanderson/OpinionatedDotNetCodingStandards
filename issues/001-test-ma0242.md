## How to implement the test

Add a `[Fact]` to
`tests/Opinionated.DotNet.CodingStandards.Tests/MeziantouAnalyzers/MeziantouAnalyzersCoreShould.cs`
(it is ~590 lines, so there is room; MA0240 and MA0241 already live there, keeping the MA02xx
block together):

```csharp
[Fact]
[RuleDoc("MA0242", "Use a value factory to compute the value only when the key is not in the ConcurrentDictionary",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0242.md")]
public async Task UseValueFactoryForConcurrentDictionary()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        namespace test;
        using System.Collections.Concurrent;
        using System.Collections.Generic;
        public class C
        {
            public List<int> M(ConcurrentDictionary<string, List<int>> dict)
                => dict.GetOrAdd("key", new List<int>());
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();
    buildOutput.HasError("MA0242").ShouldBeTrue();
}
```

### Why this shape triggers the rule

Per the [rule docs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0242.md),
`ConcurrentDictionary<TKey, TValue>.GetOrAdd(key, value)` evaluates the value eagerly even when the
key is already present. The analyzer reports only values that are **not cheap** to evaluate —
method calls, object creations, collection expressions, string concatenations, interpolated
strings, indexers, and `await` expressions. It deliberately does **not** report constants,
variables, fields, properties, casts, or built-in operators over those.

`new List<int>()` is an object creation, so it is firmly in the reported set. A bare local or
constant would be a false negative by design, so do not simplify the trigger to one.

`AddOrUpdate(key, addValue, updateValueFactory)` is the rule's other reported shape if the
`GetOrAdd` form unexpectedly fails to fire.

## Confounder playbook (exhaust before marking untestable)

Work through these in order:

1. **Add a package reference** if the rule guards on types in an external package. Not expected
   here — `ConcurrentDictionary` is in the BCL (`System.Collections.Concurrent`), already
   available on `net10.0` with no `PackageReference`.

2. **Use stub types** if the rule merely requires a type to exist in the compilation (no real
   package needed — just declare a matching type with the right name/namespace in `Program.cs`).
   Note this analyzer resolves the *real* `System.Collections.Concurrent.ConcurrentDictionary<,>`
   symbol, so a stub would not help; use the real type.

3. **Pin `LangVersion=12`** if C# 13 might route single-argument calls to a new `ReadOnlySpan`
   overload that the analyzer can't match (known to affect `CA1842`, `CA1843`). Unlikely to apply
   to `GetOrAdd`, but worth trying if the diagnostic does not appear.

4. **Set `ignore_internalsvisibleto=true`** on `CreateProjectBuilderAsync` if the rule is
   friend-assembly-sensitive (e.g., `CA1852`). Not expected for a Meziantou usage rule.

5. **Check `EnforceOnBuild`** — rules tagged `EnforceOnBuild.Never` are structurally silent at
   `dotnet build` regardless of editorconfig severity. (This is a Roslyn/IDE concept; Meziantou
   rules are ordinary build-time analyzers, so this should not apply.)

6. **Check the reporting analyzer's assembly path** — if the reporting class lives in a
   `src/Features/` path (not `src/Analyzers/`), it is IDE/LSP-only and cannot run at build time.
   MA0242 is reported by
   [`UseValueFactoryWhenUsingConcurrentDictionaryAnalyzer.cs`](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer/Rules/UseValueFactoryWhenUsingConcurrentDictionaryAnalyzer.cs)
   in the main `Meziantou.Analyzer` assembly, so it does run at build time.

7. **Check mscorlib gate** — rules that assert `System.String` is in `mscorlib` cannot fire on
   `net10.0` (it lives in `System.Private.CoreLib`). Does not apply to Meziantou rules.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
