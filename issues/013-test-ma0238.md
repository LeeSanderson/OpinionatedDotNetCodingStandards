## What to build

Add a test for rule **MA0238** — *The parameter type of an EventSource event method is not
supported* — from the `Meziantou.Analyzer` analyzer.

ETW can only serialise a fixed set of payload types: the primitives, `string`, `Guid`, `DateTime`,
`IntPtr`, enums, and `byte[]`. An event method taking anything else compiles fine but fails
manifest construction at runtime — and `EventSource` swallows that failure, so the event simply
never fires.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzersEventSourceShould.cs` (created by issue 001):

```csharp
[Fact]
[RuleDoc("MA0238", "The parameter type of an EventSource event method is not supported",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0238.md")]
public async Task ProhibitUnsupportedEventSourceParameterType()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        using System.Diagnostics.Tracing;
        namespace test;
        public sealed class Payload
        {
            public int Value { get; set; }
        }
        public sealed class MyEventSource : EventSource
        {
            [Event(1)]
            public void Started(Payload payload) => WriteEvent(1, payload);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0238").ShouldBeTrue();
}
```

### Watch out for

- **Keep the event source class `sealed`** — otherwise `MA0226` fires as well.
- **Keep the written id matching the `[Event]` id and the payload matching the parameters** so
  `MA0234` / `MA0235` / `MA0236` do not fire alongside it.
- `WriteEvent(1, payload)` binds to `WriteEvent(int, params object[])`, so the custom type compiles
  as an argument — the rule is about the *parameter* type, not a compile error.
- Good alternative unsupported types if a custom class does not fire, in order: **`Uri`** (this is
  upstream's own canonical trigger in the MA0238 docs — `[Event(1)] public void Start(Uri uri) =>
  WriteEvent(1, uri);`), then `object`, `DateTimeOffset`, `decimal`, `int[]`, or
  `System.Collections.Generic.List<string>`. Note `DateTime`, `Guid`, `byte[]`, `IntPtr`, enums,
  `string` and the primitives **are** supported, so they will not fire.
- `Payload` is declared `sealed` so it does not draw unrelated design diagnostics; that is
  incidental to the rule.

needed and this rule is expected to be straightforwardly testable. If it does not fire, work
through the standard playbook in AGENTS.md in order:

4. **Set `ignore_internalsvisibleto=true`** — try if the rule appears friend-assembly sensitive.
5. **Check `EnforceOnBuild`** in the analyzer source (`EnforceOnBuild.Never` is structurally silent
   at build).
6. **Check the reporting analyzer's assembly path** (`src/Features/` = IDE-only).
7. **Check the mscorlib gate** — not applicable to a Meziantou rule.

Work through the alternative unsupported types listed above before concluding the rule cannot fire
— the supported-type list is the analyzer's own, and a custom class may be handled by a different
rule than the one under test.

Only move the rule to `UntestableRules.cs` after exhausting all of the above.
