## What to build

Add a test for rule **MA0218** — *The language attribute is empty* — from the
`Meziantou.Analyzer` analyzer.

The rule fires when the `language` (or `lang`) attribute of a `<c>` or `<code>` element in an XML
doc comment is present but has no value, so it does not actually document the language.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzers3Should.cs` (currently ~699 lines — well under the 1000-line
split threshold, so add it to the end of the existing class):

```csharp
[Fact]
[RuleDoc("MA0218", "The language attribute is empty",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0218.md")]
public async Task ProhibitEmptyLanguageAttributeInXmlComment()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        namespace test;
        public class C
        {
            /// <summary>
            /// Sample <c language="">{ "value": 1 }</c>.
            /// </summary>
            public int Value { get; set; }
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();
    buildOutput.HasError("MA0218").ShouldBeTrue();
}
```

### Verified behaviour

This rule was confirmed to fire at build time during the package bump: adding
`/// <summary>Probe <c language="">x</c></summary>` to a source file in this repo produced
`error MA0218: The 'language' attribute is empty`. It is definitely testable — do **not** move it
to `UntestableRules.cs`.

### Watch out for

- **Use the multi-line `/// <summary>` form shown above.** A single-line
  `/// <summary>...</summary>` trips `MA0211` ("Use multi-line syntax for XML summary comments"),
  which would fail the build for the wrong reason and make the assertion ambiguous.
- The element must be `<c>` or `<code>` with an *empty* `language`/`lang` attribute. Omitting the
  attribute entirely triggers `MA0219` instead (a different rule, covered by issue 002).
