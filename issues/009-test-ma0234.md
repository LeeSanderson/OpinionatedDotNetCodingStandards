## What to build

Add a test for rule **MA0234** — *The event id written by an EventSource event method must match
its [Event] attribute* — from the `Meziantou.Analyzer` analyzer.

The `[Event(id)]` attribute declares the event in the manifest; the `WriteEvent(id, ...)` call is
what actually goes down the wire. When they disagree, the event is decoded against the wrong
schema — a bug that is invisible at compile time and at runtime.

This rule is configured as **`warning`** in
`packages/Opinionated.DotNet.CodingStandards/pkgsrc/config/analyzers/Analyzer.Meziantou.Analyzer.editorconfig`,
so it surfaces as a SARIF **error** — assert with `HasError`.

## How to implement the test

Add a `[Fact]` to `MeziantouAnalyzersEventSourceShould.cs` (created by issue 001):

```csharp
[Fact]
[RuleDoc("MA0234", "The event id written by an EventSource event method must match its [Event] attribute",
    HelpLink = "https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0234.md")]
public async Task RequireWrittenEventIdToMatchEventAttribute()
{
    using var project = await CreateProjectBuilderAsync();
    await project.AddFileAsync("Program.cs", """
        using System.Diagnostics.Tracing;
        namespace test;
        public sealed class MyEventSource : EventSource
        {
            [Event(1)]
            public void Started(string message) => WriteEvent(2, message);
        }
        public static class Program { public static int Main() => 0; }
        """);
    var buildOutput = await project.BuildAndGetOutputAsync();

    buildOutput.HasError("MA0234").ShouldBeTrue();
}
```

### Watch out for

- **Keep the class `sealed`** — otherwise `MA0226` fires as well.
- **Vary only the id.** The payload (`message`) must still exactly match the method's parameters,
  otherwise `MA0235` (issue 010) fires too and the result is ambiguous.
- Both ids must be greater than zero (`1` and `2` above), or `MA0228` (issue 003) fires as well.
- There is only one event method here, so `MA0229` / `MA0230` cannot fire.
